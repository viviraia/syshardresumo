Dados na CPU, Assembly x86-64 e gdb

Como um programa em C vira bytes e instruções, e como fazer a engenharia reversa de Assembly para C. Foi o conteúdo da AI e do Hackerlab, e é a base para entender tudo que vem depois.

Inteiros: bases, complemento de 2 e overflow

  • Bit é 0 ou 1, e 1 byte = 8 bits. A mesma sequência de bits pode ser inteiro, caractere, instrução ou endereço: o tipo é que dá o significado.
  • Hexadecimal: 1 dígito = 4 bits. 0x2F = 0010 1111 = 47, e 1 byte = 2 dígitos hex.
  • Conversão decimal→binário: divisões sucessivas por 2 (os restos, lidos de baixo para cima). Binário→hex: agrupe de 4 em 4 bits a partir da direita.
Complemento de 2 (inteiros com sinal)

Com w bits, o bit mais significativo vale −2w−1. Faixa: −2w−1 … 2w−1−1. Sem sinal: 0 … 2w−1.

Negar: inverta todos os bits e some 1 (−x = ~x + 1). −1 é tudo 1 (0xFF…FF).

Exemplo: char ch = 0b10000111; imprime −121 (−128 + 7), porque char tem sinal.

  • Overflow: só os w bits menos significativos sobrevivem. unsigned short x = 80000; guarda 80000 mod 65536 = 14464.
  • unsigned short x = -1; guarda 16 bits em 1, ou seja, 65535. Os bits são os mesmos e a interpretação muda.
  • Extensão de sinal: um char −126 (0x82) promovido a int vira 0xffffff82. Um unsigned char seria estendido com zeros (0x00000082).
  • Operações bit a bit: & (E), | (OU), ^ (XOR), ~ (NÃO), <<, >>.
    • x & 1 testa se x é ímpar.
    • x << k equivale a x · 2k.
    • >> em signed é aritmético (repete o sinal) e em unsigned é lógico (entra 0).

Representação de dados na RAM

  • Little endian (x86-64): o byte menos significativo fica no menor endereço. int n = 0x0a0c0b0d; aparece na memória como 0d 0b 0c 0a. No big endian é o contrário. A unidade é o byte: dentro de um byte nada se inverte.
  • Arrays mantêm a ordem dos elementos, e cada elemento é little endian: short arr[] = {0x1122, 0x3344} fica 22 11 44 33.
  • Strings são arrays de char terminados em '\0': "Oi C :-)" ocupa 9 bytes. Os códigos ASCII mais úteis: '0'=0x30, 'A'=0x41, 'a'=0x61, ' '=0x20.
  • Aritmética de ponteiros: p + 1 soma sizeof(*p) bytes (4 para int*, 8 para long*), e *(x+i) ≡ x[i].
  • union: os campos compartilham o mesmo endereço, e o tamanho é o do maior campo.

struct e alinhamento

Uma struct é um bloco contíguo com os campos na ordem declarada; o compilador não reordena. Um campo de K bytes precisa ficar num endereço múltiplo de K, e o compilador insere padding para isso. O tamanho total é múltiplo do maior alinhamento entre os campos. O endereço da struct é igual ao do primeiro campo.

struct player {
    char name[20];   // offset 0..19
                     // 4 bytes de padding (level precisa de múltiplo de 8)
    long level;      // offset 24..31
    char icon_id;    // offset 32
                     // 7 bytes de padding
    long score;      // offset 40..47
};                   // sizeof = 48 (11 bytes "desperdiçados")

Pelos endereços impressos dá para inferir o tamanho máximo de cada campo: é a diferença entre endereços consecutivos.

O tamanho do registrador indica o tipo em C:

  • r.. (8 bytes) é long ou ponteiro;
  • e.. e ..d (4 bytes) são int;
  • ..x de duas letras (2 bytes) é short;
  • ..l/..h (1 byte) é char.

O ponto flutuante usa %xmm0–7 nos argumentos e %xmm0 no retorno. Os registradores menores são "virtuais": escrever em %eax zera os 32 bits de cima de %rax.

Sufixos das instruções: b = 1 byte, w = 2, l = 4, q = 8 (movl, addq...).

Os casts seguem o padrão MOV t s d: t = z (zero) ou s (sinal); s/d = tamanhos b w l q. Ex.: movzwq é unsigned short → unsigned long.

LEA: aritmética ou &?
  • Se usa %rsp, é sempre &variável_local.
  • Se os registradores guardam números usados em contas, é aritmética: lea (%rdi,%rdi,4),%eax = a*5, e lea -2(%rsi),%rax = b - 2.
  • Se o resultado é usado depois como endereço (mov (%rax)), é cálculo de endereço (&v[i]).
  • lea é a única instrução com a sintaxe D(r1,r2,S) que não acessa a memória.

Flags, comparações e saltos

Toda operação aritmética seta as flags CF (carry, para unsigned), ZF (zero), SF (sinal) e OF (overflow, para signed). Há duas instruções que só setam flags:

  • cmp b, a calcula a − b e compara a com b (lê-se "o segundo em relação ao primeiro");
  • test b, a calcula a & b. test %rdi,%rdi testa o sinal/zero de rdi, e test $1,%dil testa se é ímpar.

Esses sufixos aparecem em três famílias:

  • set* grava 0/1 em um registrador de 1 byte (sete %al), geralmente seguido de movzbl %al,%eax;
  • j* salta se a condição valer;
  • jmp salta sempre (incondicional).

Por isso o par cmp/test + j* vira if (cond) goto label;. Ver seta/setb/ja/jbe indica que os tipos são unsigned; ver g/l indica signed.

Algoritmo de engenharia reversa (Assembly → C)

  1. Assinatura: liste %rdi, %rsi, %rdx, %rcx, %r8, %r9 e veja quais são lidos antes de serem escritos: esses são os argumentos.
  2. Tipos: o tamanho do registrador e o set*/j* usado (signed ou unsigned) dão o tipo. Registrador de 64 bits usado com (%reg) é ponteiro. A escala do D(r1,r2,S) dá o tipo do elemento (S=4 é int*).
  3. Retorno: o que fica em %rax/%eax antes do ret. Se nada é escrito em %rax, a função é void.
  4. Nomeie cada registrador (um nome por tamanho diferente).
  5. Traduza instrução por instrução para gotoC (if (...) goto x;).
  6. Desenhe as setas dos saltos: um salto para trás é um loop, um salto para frente é um if/else.
  7. Refatore para C legível. Lembre que o compilador inverte as condições e reordena blocos (o else pode vir primeiro, e a > 4 equivale a a >= 5).

Exemplo: if/else com expressões compostas

cmp  $0x4,%rdi ; setg %dl       # dl = a > 4
test %rsi,%rsi ; setle %al      # al = b <= 0
test %al,%dl   ; jne  L1        # if (dl && al) goto L1
mov  %rdi,%rax ; sub %rsi,%rax ; ret     # return a - b
L1: lea (%rdi,%rsi,1),%rax ; ret         # return a + b
long exemplo2(long a, long b) {
    if (a >= 5 && b <= 0) return a + b;
    else return a - b;
}

Exemplo: loop (salto para trás)

soma_2n:  mov $0x1,%eax
          jmp L2
L1:       shr %edi              # a = a >> 1
          add $0x1,%eax         # res++
L2:       cmp $0x1,%edi
          ja  L1                # while (a > 1) — unsigned!
          ret
int soma_2n(unsigned int a) {
    int res = 1;
    while (a > 1) { a = a / 2; res++; }
    return res;
}

Exemplo: array

soma:  mov $0,%edx ; mov $0,%eax ; jmp L2
L1:    movslq %edx,%rcx               # i (int) -> long para indexar
       add (%rdi,%rcx,4),%eax         # res += vec[i]  (escala 4 => int*)
       add $1,%edx                    # i++
L2:    cmp %esi,%edx ; jl L1          # i < n
       ret
int soma(int *vec, int n) {
    int res = 0;
    for (int i = 0; i < n; i++) res += vec[i];
    return res;
}

Índices constantes viram deslocamentos fixos: mov $0, 0x28(%rdi) é v[5] = 0 num long* (5×8 = 40 = 0x28), e movw $0x14, 0x4(%rdi) é v[2] = 20 num short*.

Variáveis locais, globais e strings

  • Locais na pilha: a função começa com sub $0x10,%rsp (reserva 16 bytes) e termina com add $0x10,%rsp; essas duas instruções não têm equivalente em C. Todo deslocamento relativo a %rsp é uma variável local. Com mov é leitura/escrita; com lea é &local. O compilador só coloca uma variável na pilha quando precisa do endereço dela (ex.: o scanf).
  • Globais e constantes: são acessadas relativas a %rip, como mov 0x2ea1(%rip),%eax # <times_called>. O deslocamento muda de instrução para instrução, mas o endereço final é o mesmo, e o gdb mostra o endereço calculado no comentário. Strings em .rodata são só para leitura.
sub  $0x18,%rsp
lea  0xc(%rsp),%rsi            # &n
lea  0xeab(%rip),%rdi          # "%d"   (x/s 0x2004)
mov  $0,%eax
call __isoc99_scanf@plt        # scanf("%d", &n)
cmpl $0,0xc(%rsp) ; js neg     # if (n < 0)
...

O mov $0,%eax antes de chamar funções variádicas (printf/scanf) indica que nenhum argumento é de ponto flutuante. endbr64 é uma proteção de controle de fluxo e pode ser ignorado.
