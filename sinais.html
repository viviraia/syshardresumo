Sinais: envio, captura e bloqueio

Sinais são o jeito de o SO (ou de outro processo) avisar um processo de que algo aconteceu. Na AF aparecem como "capture o Ctrl+C, salve o estado em arquivo e termine".

O que é um sinal

Definição

Um sinal é uma notificação assíncrona enviada a um processo para indicar que algo ocorreu: um erro ou exceção de hardware, uma mudança no sistema, ou o pedido do usuário para parar ou finalizar. É uma "exceção de software": o kernel interrompe o fluxo normal do processo para entregá-lo. O sinal não carrega dados, só o número.

Quem envia:

  • o kernel, ao detectar um evento: divisão por zero (SIGFPE), acesso inválido à memória (SIGSEGV), filho terminou (SIGCHLD), Ctrl+C no terminal (SIGINT);
  • outro processo, via a syscall kill (do mesmo usuário; o root pode enviar para qualquer processo).

O que o destinatário pode fazer:

  • ignorar;
  • terminar (às vezes com core dump);
  • parar/continuar;
  • capturar, executando um signal handler definido pelo programador.

Um sinal também pode ficar bloqueado (pendente) até ser desbloqueado.

A captura segue este caminho:

  1. o sinal chega durante a instrução Icurr;
  2. o controle passa para o handler;
  3. o handler executa;
  4. o handler retorna para a instrução Inext, e o programa continua de onde parou.

Enviando sinais

No terminal

kill -9 1234            # SIGKILL para o pid 1234
kill -s SIGINT 1234     # SIGINT
kill -USR1 1234         # SIGUSR1
kill 1234               # sem opção = SIGTERM
kill -l                 # lista os sinais
./prog ; kill -l $?     # após o término: mostra o sinal que matou o prog (ex.: INT)

O shell devolve $? = 128 + nº do sinal quando o processo morre por sinal (130 = SIGINT, 137 = SIGKILL).

No programa

#include <signal.h>
int kill(pid_t pid, int sig);   // envia sig para pid
int raise(int sig);             // envia para si mesmo (= kill(getpid(), sig))

kill(filho, SIGKILL);           // pai mata o filho
kill(getpid(), SIGINT);         // processo manda SIGINT para si próprio
// pai espera 10 s e mata o filho SÓ se ele ainda estiver rodando (WNOHANG)
sleep(10);
int st;
if (waitpid(filho, &st, WNOHANG) == 0) {   // 0 = ainda não terminou
    kill(filho, SIGKILL);
    waitpid(filho, &st, 0);
}
if (WIFSIGNALED(st)) printf("filho morreu por %s\n", strsignal(WTERMSIG(st)));

Capturando sinais com sigaction

Use sigaction, não signal

A função signal() é considerada obsoleta. A disciplina usa sigaction, que permite configurar o bloqueio de sinais durante o handler.

#include <signal.h>
int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);

struct sigaction {
    void     (*sa_handler)(int);   // função handler, SIG_DFL (padrão) ou SIG_IGN (ignorar)
    sigset_t sa_mask;              // sinais BLOQUEADOS enquanto o handler roda
    int      sa_flags;             // opções: usamos 0
    /* ... */
};

Receita (decore!)

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>

void sig_handler(int num) {          // assinatura obrigatória: void f(int)
    printf("Recebi o sinal %d\n", num);
}

int main() {
    struct sigaction s;
    s.sa_handler = sig_handler;      // 1) a função
    sigemptyset(&s.sa_mask);         // 2) máscara vazia (não bloqueia nada extra)
    s.sa_flags = 0;                  // 3) sem flags
    sigaction(SIGINT, &s, NULL);     // 4) registra para SIGINT (oldact = NULL)

    printf("Meu pid: %d\n", getpid());
    while (1) sleep(1);
    return 0;
}

Compile e mande sinais de outro terminal com kill -s SIGINT <pid>. Para não precisar de dois terminais, rode com ./prog & e use o pid mostrado.

Sair só no 3º Ctrl+C, terminando DE VERDADE pelo sinal

Com exit(0) no handler, o shell acha que o programa terminou normalmente. O correto é restaurar o comportamento padrão (SIG_DFL) e reenviar o sinal para si mesmo:

int contador = 0;

void sig_handler(int num) {
    contador++;
    printf("Chamou Ctrl+C\n");
    if (contador == 3) {
        struct sigaction padrao;
        padrao.sa_handler = SIG_DFL;     // volta ao padrão (terminar)
        padrao.sa_flags = 0;
        sigemptyset(&padrao.sa_mask);
        sigaction(SIGINT, &padrao, NULL);
        kill(getpid(), SIGINT);          // ou raise(SIGINT): agora termina por SIGINT
    }
}

Padrão da AF: ao receber SIGINT, salvar o estado e encerrar

Na Q3 do simulado, o π é calculado num laço infinito. Os pontos se dividem assim: mostrar o PID (10%), imprimir o valor no SIGINT e encerrar (60%) e salvar em pi.txt com open/write (30%).

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <fcntl.h>

double pi = 0.0;                      // global: o handler enxerga

void exporta_pi() {
    int fd = open("pi.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    char buf[64];
    int n = snprintf(buf, sizeof(buf), "%f\n", pi);
    write(fd, buf, n);
    close(fd);
}

void aproxima_pi(void);              // já vem pronta no enunciado (laço infinito)

void handler_sigint(int sig) {
    printf("pi = %f\n", pi);
    exporta_pi();
    exit(0);                          // ou SIG_DFL + raise(SIGINT)
}

int main() {
    printf("PID: %d\n", getpid());
    struct sigaction s;
    s.sa_handler = handler_sigint;
    sigemptyset(&s.sa_mask);
    s.sa_flags = 0;
    sigaction(SIGINT, &s, NULL);      // registrar NA MAIN, antes do laço
    aproxima_pi();                    // laço infinito
}
Checklist para a questão de sinais
  • O handler é uma função separada com a assinatura void h(int), registrada no main, antes do trabalho começar.
  • O dado que o handler usa está numa variável global.
  • Arquivo só com open/write/close (o número vira texto com snprintf).
  • Mostre o PID com printf("%d\n", getpid()).
  • Teste com Ctrl+C e com kill -INT <pid> de outro terminal, e confira o arquivo com cat.

Sinais e concorrência: handlers aninhados

Um handler pode ser interrompido por outro handler. Exemplo: o handler de SIGINT está rodando, chega um SIGTERM e o handler de SIGTERM roda "por cima". Só depois que ele termina o de SIGINT continua. Já um handler não é interrompido pelo mesmo sinal: durante o handler de A, um novo A fica pendente (e vários A pendentes viram um só, porque sinais não são enfileirados).

Isso gera race conditions quando dois handlers mexem na mesma variável global, chamam printf ou usam errno. No experimento sinais-concorrentes.c (SIGINT, SIGTERM, SIGINT enviados rapidamente), a variável status ficou inconsistente.

Erros conceituais dos slides
  • O main esperar informação vinda do handler (checar uma flag em vários lugares): errado. O handler deve ser autocontido.
  • O main tentar se sincronizar com o handler ("e se o código já passou deste ponto?"): errado. O handler pode ocorrer a qualquer momento.

Bloqueio de sinais com sa_mask

Um sinal bloqueado fica pendente e é entregue quando for desbloqueado. Bloquear é temporário e não descarta o sinal. Com sa_mask, os sinais da máscara ficam bloqueados enquanto aquele handler executa.

// handler de SIGINT não pode ser interrompido por SIGTERM...
struct sigaction s_int;
s_int.sa_handler = handler_int;
s_int.sa_flags = 0;
sigemptyset(&s_int.sa_mask);
sigaddset(&s_int.sa_mask, SIGTERM);      // bloqueia SIGTERM durante handler_int
sigaction(SIGINT, &s_int, NULL);

// ...e o de SIGTERM não pode ser interrompido por SIGINT (corrige o outro lado)
struct sigaction s_term;
s_term.sa_handler = handler_term;
s_term.sa_flags = 0;
sigemptyset(&s_term.sa_mask);
sigaddset(&s_term.sa_mask, SIGINT);
sigaction(SIGTERM, &s_term, NULL);

As funções de conjunto (man sigsetops) são sigemptyset, sigfillset, sigaddset, sigdelset e sigismember. Para bloquear fora de handlers, use sigprocmask(SIG_BLOCK, &set, NULL).

Ctrl+Z e SIGCONT

void handler_tstp(int s) {
    printf("Vou parar!\n");
    struct sigaction padrao;            // volta ao padrão (parar) e reenvia
    padrao.sa_handler = SIG_DFL;
    padrao.sa_flags = 0;
    sigemptyset(&padrao.sa_mask);
    sigaction(SIGTSTP, &padrao, NULL);
    raise(SIGTSTP);
}
void handler_cont(int s) {
    printf("Continuando!\n");
    // re-registra o handler de SIGTSTP para a próxima vez
    struct sigaction t;
    t.sa_handler = handler_tstp;
    t.sa_flags = 0;
    sigemptyset(&t.sa_mask);
    sigaction(SIGTSTP, &t, NULL);
}

Sinais interrompem chamadas bloqueantes

Ao chegar um sinal capturado, as chamadas que bloqueiam o processo (sleep, wait, read, write) podem ser interrompidas e retornar antes da hora:

  • sleep(n) retorna o número de segundos que faltavam (0 se dormiu tudo). É assim que se verifica se ele dormiu o tempo todo (man 3 sleep, RETURN VALUE).
  • read/wait podem retornar -1 com errno == EINTR.
unsigned int falta = 10;
while (falta > 0) falta = sleep(falta);   // dorme os 10 s mesmo recebendo sinais

No programa sleep_longo.c: com um handler de SIGTERM, o sleep é cortado e o programa segue. Sem handler, o SIGTERM simplesmente mata o processo.

Revisão: o pai descobrindo o sinal do filho

pid_t f = fork();
if (f == 0) {
    int z = 0;
    int x = 10 / z;      // SIGFPE no filho
    return x;
}
int st;
wait(&st);
printf("WIFEXITED=%d WIFSIGNALED=%d WTERMSIG=%d (%s)\n",
       WIFEXITED(st), WIFSIGNALED(st), WTERMSIG(st), strsignal(WTERMSIG(st)));
// WIFEXITED=0 WIFSIGNALED=1 WTERMSIG=8 (Floating point exception)

Resumo relâmpago

  • Sinal é uma notificação assíncrona. As ações possíveis são ignorar, terminar, parar/continuar ou capturar com um handler.
  • SIGKILL e SIGSTOP não podem ser capturados nem ignorados. Ctrl+C gera SIGINT e Ctrl+Z gera SIGTSTP.
  • kill(pid, sig), raise(sig), kill -s SIG pid, kill -l $?.
  • A receita do sigaction: sa_handler + sigemptyset(&sa_mask) + sa_flags = 0 + sigaction(SIG, &s, NULL).
  • Para terminar "de verdade" pelo sinal: SIG_DFL + raise.
  • Handlers aninham com sinais diferentes. Use sigaddset(&s.sa_mask, OUTRO) para evitar a race.
  • Includes: <signal.h>, <unistd.h>, <string.h> (para strsignal). Manuais: man 7 signal, man 2 sigaction, man sigsetops, man 2 kill.
