Semáforos e modelos de concorrência

O mutex protege dados. O semáforo sincroniza o progresso das threads: "B só começa depois que A terminar", "no máximo 3 por vez", "espere todos chegarem".

Definição

Semáforo

Um inteiro especial que nunca fica negativo, manipulado só por duas operações atômicas:

  • POST (sem_post): aumenta 1 e, se houver alguém esperando, acorda uma thread.
  • WAIT (sem_wait): se o valor for positivo, diminui 1 e segue; se for 0, fica esperando até alguém fazer post.

O valor representa quantas "permissões" ou "avisos" estão disponíveis.

Duas tarefas podem rodar em paralelo se (1) não compartilham nenhuma informação, ou (2) compartilham mas têm mecanismos de sincronização tais que toda ordem de execução possível leva ao mesmo resultado. Os semáforos servem para o caso (2).

"Podem ser feitas em qualquer ordem" não quer dizer "em paralelo". Quer dizer que A inteira pode vir antes ou depois de B inteira, com o mesmo resultado.

API POSIX (unnamed semaphores)

#include <semaphore.h>

int sem_init(sem_t *sem, int pshared, unsigned int valor); // pshared = 0: entre threads do mesmo processo
int sem_wait(sem_t *sem);
int sem_post(sem_t *sem);
int sem_destroy(sem_t *sem);

sem_t s;
sem_init(&s, 0, 0);     // valor inicial 0: "ainda não aconteceu"
sem_post(&s);
sem_wait(&s);
sem_destroy(&s);
  • Unnamed (sem_init): ficam na memória do processo, usados entre threads. É o que usamos.
  • Named (sem_open("/nome", ...)): têm um nome global no sistema, usados entre processos diferentes.
  • O semáforo precisa ser compartilhado pelas threads: global, ou passe sem_t * pela struct de argumentos. Nunca passe uma cópia (sem_t por valor).
  • Veja man sem_overview.

Rendez-vous (encontro de duas threads)

A e B podem ocorrer em qualquer ordem, mas ambas antes de C e D. As ordens válidas são ABCD, ABDC, BACD e BADC; qualquer ordem com C ou D antes de A ou B é inválida (ex.: ACBD).

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <semaphore.h>

typedef struct { sem_t *s1, *s2; } t_arg;

void *thread1(void *_arg) {
    t_arg *arg = _arg;
    printf("A\n");
    sem_post(arg->s1);   // "thread1 chegou"
    sem_wait(arg->s2);   // espera "thread2 chegou"
    printf("C\n");
    return NULL;
}
void *thread2(void *_arg) {
    t_arg *arg = _arg;
    printf("B\n");
    sem_post(arg->s2);   // "thread2 chegou"
    sem_wait(arg->s1);   // espera "thread1 chegou"
    printf("D\n");
    return NULL;
}
int main() {
    pthread_t tid[2];
    sem_t s1, s2;
    sem_init(&s1, 0, 0);
    sem_init(&s2, 0, 0);
    t_arg arg = { &s1, &s2 };          // pode ficar na pilha do main: o main espera o join
    pthread_create(&tid[0], NULL, thread1, &arg);
    pthread_create(&tid[1], NULL, thread2, &arg);
    pthread_join(tid[0], NULL);
    pthread_join(tid[1], NULL);
    sem_destroy(&s1);
    sem_destroy(&s2);
    return 0;
}
Perguntas que caem
  • Iniciar os semáforos com 1? Não: quem espera por ele passaria direto, sem o outro ter chegado.
  • Inverter para wait antes do post?
    • Em uma thread só, ainda funciona, mas impõe uma ordem fixa (uma sempre espera a outra).
    • Nas duas, dá deadlock: cada uma espera um aviso que a outra nunca envia.

Receita: do diagrama de dependências aos semáforos

A Q1 da AF mostra uma figura com as partes de 4 ou 5 threads e setas de dependência ("D só pode começar depois de A e B"). Vale 40% criar as threads e 60% sincronizar sem criar dependências novas (se criar, a questão vale no máximo 50%).

Algoritmo infalível
  1. Liste cada seta X → Y ("Y depende de X").
  2. Para cada parte X que tem setas saindo, crie um semáforo sX iniciado em 0.
  3. Logo depois do printf("X"), faça sem_post(&sX) uma vez para cada seta que sai de X.
  4. Logo antes do printf("Y"), faça sem_wait(&sX) para cada X de que Y depende.
  5. As dependências dentro da mesma thread (A antes de E na thread1) já são garantidas pela ordem do código: não precisam de semáforo.
  6. Crie as threads num laço (vetor de ponteiros para função) e faça join em todas.

Por que um post por seta? Se A libera B e D, e A desse um post só, apenas um deles passaria. Com dois posts no mesmo sA, cada um consome um. Alternativa equivalente: semáforos separados sA_B e sA_D.

// Exemplo: A -> C, B -> C, C -> D   (A na t1, B na t2, C e D na t3)
sem_t sA, sB;           // globais; no main: sem_init(&sA, 0, 0); sem_init(&sB, 0, 0);

void *t1(void *a) { printf("A\n"); sem_post(&sA); return NULL; }
void *t2(void *a) { printf("B\n"); sem_post(&sB); return NULL; }
void *t3(void *a) {
    sem_wait(&sA);          // C depende de A
    sem_wait(&sB);          // C depende de B
    printf("C\n");
    printf("D\n");          // D depois de C: mesma thread, já é garantido
    return NULL;
}

// criando em laço:
void *(*funcs[3])(void *) = {t1, t2, t3};
pthread_t tids[3];
for (int i = 0; i < 3; i++) pthread_create(&tids[i], NULL, funcs[i], NULL);
for (int i = 0; i < 3; i++) pthread_join(tids[i], NULL);
Como perder pontos
  • Usar pthread_join no meio para impor ordem: isso cria dependências extras e serializa tudo.
  • Usar sleep para "acertar" a ordem: não é sincronização.
  • Pôr o sem_post antes do printf da parte, liberando cedo demais.
  • Fazer wait num semáforo que ninguém posta, ou postar menos vezes que o número de dependentes: deadlock.
  • Alterar ou adicionar printfs (é proibido no enunciado).

Barreira (generalização do RDV para N threads)

N threads rodando o mesmo código precisam esperar todas chegarem antes de qualquer uma imprimir "Depois da barreira". Usam-se três coisas:

  • um contador compartilhado num_barrier, que precisa de mutex por ser compartilhado e escrito;
  • um semáforo sem_barrier iniciado em 0;
  • a regra de que a última thread a chegar faz N−1 posts, porque cada sem_post libera exatamente uma thread que está no sem_wait.
typedef struct {
    int n;                       // total de threads
    int *num_barrier;            // quantas já chegaram
    pthread_mutex_t *mutex;
    sem_t *sem_barrier;
} t_bar;

void *tarefa(void *_arg) {
    t_bar *b = _arg;
    printf("Antes da barreira\n");

    pthread_mutex_lock(b->mutex);
    (*b->num_barrier)++;
    int ultimo = (*b->num_barrier == b->n);
    pthread_mutex_unlock(b->mutex);

    if (ultimo) {
        for (int i = 0; i < b->n - 1; i++) sem_post(b->sem_barrier);  // libera as outras N-1
    } else {
        sem_wait(b->sem_barrier);                                     // espera a última
    }

    printf("Depois da barreira\n");
    return NULL;
}

Outra forma: todas fazem sem_wait e a última posta N vezes (incluindo ela mesma). Também é válido.

Limitar a MAX threads executando ao mesmo tempo

É um semáforo iniciado com MAX (o número de "vagas"). Cada thread faz sem_wait para entrar e sem_post para sair. Criam-se todas as threads, mas só MAX passam do wait por vez. Este é o "respeitar a quantidade máxima de threads" da Q4 do simulado (30%).

#define N   10
#define MAX 2
typedef struct { sem_t *sem; } arg_thread_t;

void *faz_algo(void *arg_) {
    arg_thread_t *arg = arg_;
    sem_wait(arg->sem);            // pede uma vaga (bloqueia se já há MAX rodando)
    printf("Thread executando!\n");
    trabalho_pesado();
    printf("Thread vai finalizar!\n");
    sem_post(arg->sem);            // devolve a vaga
    return NULL;
}

int main() {
    sem_t semaph;
    sem_init(&semaph, 0, MAX);     // MAX vagas
    arg_thread_t *arg = malloc(sizeof(arg_thread_t));
    arg->sem = &semaph;
    pthread_t *tid = malloc(sizeof(pthread_t) * N);
    for (int i = 0; i < N; i++) pthread_create(&tid[i], NULL, faz_algo, arg);
    for (int i = 0; i < N; i++) pthread_join(tid[i], NULL);
    sem_destroy(&semaph);
    free(tid);
    free(arg);
}

Para conferir, com MAX = 2 e 6 tarefas de 1 s, o time deve dar cerca de 3 s; com MAX = 6, cerca de 1 s.

Produtor-consumidor (buffer circular)

Produtores geram itens e consumidores os processam, compartilhando um buffer limitado de tamanho T, implementado como fila circular (índices que voltam a 0 com % T). São três sincronizações:

  • vazias, iniciado em T: o produtor faz wait (espera se o buffer está cheio) e o consumidor faz post depois de retirar;
  • cheias, iniciado em 0: o consumidor faz wait (espera se o buffer está vazio) e o produtor faz post depois de inserir;
  • um mutex para proteger os índices e o buffer quando há vários produtores ou consumidores.
#define T 5
int buffer[T];
int ini = 0, fim = 0;                 // consome em ini, produz em fim
sem_t vazias, cheias;                 // sem_init(&vazias,0,T); sem_init(&cheias,0,0);
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;

void *produtor(void *a) {
    while (1) {
        int item = rand() % 100;
        sleep(rand() % 3);
        sem_wait(&vazias);            // há espaço?
        pthread_mutex_lock(&m);
        buffer[fim] = item;
        fim = (fim + 1) % T;
        pthread_mutex_unlock(&m);
        sem_post(&cheias);            // avisa: +1 item
    }
}
void *consumidor(void *a) {
    while (1) {
        sem_wait(&cheias);            // há item?
        pthread_mutex_lock(&m);
        int item = buffer[ini];
        ini = (ini + 1) % T;
        pthread_mutex_unlock(&m);
        sem_post(&vazias);            // avisa: +1 espaço
        printf("consumi %d\n", item);
        sleep(rand() % 3);
    }
}
A ordem importa

Faça sem_wait antes do mutex_lock. Se travar o mutex e depois esperar pelo semáforo, você dorme segurando a trava e o outro lado nunca consegue postar: deadlock.

A versão com M produtores e N consumidores usa o mesmo código, só criando mais threads (por isso o mutex é obrigatório). O plano de aula também cita o problema de leitores-escritores: vários leitores podem ler juntos, mas o escritor precisa de exclusividade, com um contador de leitores protegido por mutex e um semáforo de "sala vazia".

Um semáforo iniciado em 1 (binário) funciona como mutex, mas na prova use o mutex para dados e o semáforo para ordem e vagas.

Resumo relâmpago

  • sem_init(&s, 0, v): v = 0 para "evento ainda não ocorreu"; v = MAX para "MAX vagas".
  • Para dependências: post depois da parte, um por dependente; wait antes da parte, um por dependência.
  • RDV: post do seu e wait do outro. Inverter nas duas threads causa deadlock.
  • Barreira: contador + mutex + N−1 posts da última thread.
  • Produtor-consumidor: vazias = T, cheias = 0, mutex; wait antes do lock.
  • Include <semaphore.h> e compilar com -pthread.
