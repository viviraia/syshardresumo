Entrada/Saída com chamadas POSIX

Na prova, arquivos são manipulados somente com open, read, write e close. Nada de fopen, fprintf, fgets ou getline.

Tudo é arquivo

  • Em Unix, um arquivo é uma sequência de bytes B0…Bm-1. Para o kernel não existe diferença entre "texto" e "binário".
  • Dispositivos de E/S também são arquivos (/dev), e o kernel expõe estruturas via /proc e /sys.
  • Tipos de arquivo:
    • regular: dados arbitrários;
    • diretório: array de links nome→arquivo, sempre com . e ..;
    • socket: comunicação com outra máquina;
    • pipe/FIFO: comunicação entre processos da mesma máquina;
    • link simbólico: um "ponteiro" para outro arquivo;
    • dispositivo: de bloco ou de caractere.
  • Fim de linha: \n no Linux/macOS e \r\n no Windows e em protocolos de internet.
  • Cada processo tem um diretório corrente (cwd), que muda com chdir(). man hier descreve a hierarquia de pastas.
File descriptor (fd)

Um int que identifica um arquivo aberto no processo. Todo processo criado pelo shell já nasce com três abertos:

fdnomemacro
0entrada padrão (stdin)STDIN_FILENO
1saída padrão (stdout)STDOUT_FILENO
2saída de erro (stderr)STDERR_FILENO

Por isso write(1, "oi\n", 3) imprime no terminal.

open e close

#include <fcntl.h>      // open e flags O_*
#include <sys/stat.h>   // modos
#include <unistd.h>     // read, write, close

int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);   // mode só se criar (O_CREAT)
int close(int fd);

open retorna o fd (≥ 0) ou -1 em erro, e preenche errno.

FlagEfeito
O_RDONLY / O_WRONLY / O_RDWRSomente leitura, somente escrita ou leitura e escrita (escolha uma).
O_CREATCria o arquivo se não existir (exige o 3º argumento mode).
O_TRUNCSe já existe, apaga o conteúdo (tamanho 0) antes de escrever.
O_APPENDToda escrita vai para o fim do arquivo.
O_EXCL (com O_CREAT)Falha se o arquivo já existe (errno == EEXIST). Serve para não sobrescrever sem perguntar.
int fd = open("saida.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
if (fd == -1) {
    perror("open");        // imprime a mensagem do errno, ex.: "open: Permission denied"
    exit(1);
}
// ... usa fd ...
close(fd);                 // não feche duas vezes o mesmo fd!
Pegadinha do experimento "100a / 3b"

Ao copiar um arquivo de 3 bytes ("bbb") por cima de um de 100 bytes ("aaa…") sem O_TRUNC, o resultado é bbbaaaa… (97 'a' sobram): o open não apaga o conteúdo antigo, e o write só sobrescreve os primeiros bytes. Use O_TRUNC (ou O_EXCL para não sobrescrever).

read e write

ssize_t read(int fd, void *buf, size_t count);          // lê ATÉ count bytes para buf
ssize_t write(int fd, const void *buf, size_t count);   // escreve count bytes de buf
  • Ambas retornam o número de bytes efetivamente lidos ou escritos, e -1 em erro.
  • read retorna 0 quando o arquivo acabou (EOF). É assim que se detecta o fim.
  • São síncronas: bloqueiam até haver dados (no terminal, até você digitar).
  • Elas não colocam '\0'. Se for tratar como string, coloque você mesmo: buf[n] = '\0';.
  • Cada chamada avança a posição corrente do arquivo. lseek(fd, 0, SEEK_SET) volta ao início.
Short counts

O read/write pode transferir menos bytes que o pedido. Isso acontece:

  • no EOF;
  • ao ler linhas do terminal;
  • com sockets e pipes;
  • quando a chamada é interrompida por um sinal.

Nunca acontece ao ler arquivos regulares (exceto no EOF) nem ao escrever neles. Por isso um laço de leitura robusto testa o retorno.

Lendo um arquivo inteiro, byte a byte

int fd = open(argv[1], O_RDONLY);
char c;
while (read(fd, &c, 1) > 0) {   // > 0: ainda há bytes (0 = EOF, -1 = erro)
    printf("%c", c);
}
close(fd);

copy_file com buffer (exercício da aula)

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main(int argc, char *argv[]) {
    if (argc != 3) { printf("uso: %s origem destino\n", argv[0]); return 1; }
    int in = open(argv[1], O_RDONLY);
    if (in == -1) { perror("origem"); return 1; }
    int out = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (out == -1) { perror("destino"); close(in); return 1; }

    char buf[4096];
    ssize_t n;
    while ((n = read(in, buf, sizeof(buf))) > 0) {
        write(out, buf, n);         // escreve exatamente o que foi lido (n, não sizeof)
    }
    close(in);
    close(out);
    return 0;
}

Desempenho: com um buffer de 1 byte o programa faz uma syscall por byte (milhões de trocas para o kernel). Com um buffer maior (100, 4096 bytes) faz muito menos chamadas, e por isso fica muito mais rápido. Meça com time, gere arquivos grandes com dd if=/dev/urandom of=ex.bin bs=1M count=100 e confira com diff ou cmp.

Ler uma linha de tamanho arbitrário (cai muito!)

Apareceu na revisão (aula 20) e na Q4 do simulado: "char *read_line(int fd) que retorna a próxima linha sem o \n, ou NULL no fim, usando só read". Pelas rubricas, a versão com tamanho máximo fixo vale 50%; a de tamanho arbitrário, com realloc, vale 100%.

char *read_line(int fd) {
    int cap = 16, len = 0;
    char *buf = malloc(cap);
    char c;
    int lidos;

    while ((lidos = read(fd, &c, 1)) > 0) {
        if (c == '\n') break;          // fim da linha (não guarda o \n)
        if (len + 1 >= cap) {          // reserva espaço para o '\0'
            cap *= 2;
            buf = realloc(buf, cap);
        }
        buf[len++] = c;
    }
    if (lidos <= 0 && len == 0) {      // EOF e nada lido: acabou
        free(buf);
        return NULL;
    }
    buf[len] = '\0';
    return buf;                        // quem chama deve dar free()
}

// uso:
char *linha;
while ((linha = read_line(fd)) != NULL) {
    if (linha[0] >= 'A' && linha[0] <= 'Z') printf("%s\n", linha);   // só as que começam com maiúscula
    free(linha);
}
Cuidados que tiram ponto
  • A última linha sem \n precisa ser retornada (o lidos == 0 com len > 0).
  • Não esqueça o '\0' nem o free de cada linha: o valgrind acusa vazamento.
  • Se tiver \r\n (arquivo do Windows), remova o \r também.

Escrever e ler números em arquivo texto

write escreve bytes, não números. Para gravar um double ou long "em formato de texto" (ex.: pi.txt do simulado), converta com snprintf e escreva a string:

void salva_double(const char *nome, double valor) {
    int fd = open(nome, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) { perror("open"); return; }
    char buf[64];
    int n = snprintf(buf, sizeof(buf), "%f\n", valor);   // n = quantos chars
    write(fd, buf, n);
    close(fd);
}

double le_double(const char *nome) {
    int fd = open(nome, O_RDONLY);
    if (fd == -1) return 0.0;
    char buf[64];
    int n = read(fd, buf, sizeof(buf) - 1);
    close(fd);
    if (n <= 0) return 0.0;
    buf[n] = '\0';
    return atof(buf);                                    // texto -> número
}

Para imprimir sem printf: write(STDOUT_FILENO, buf, n). O write(fd, &valor, sizeof(valor)) grava em binário, ilegível com cat; só use se o enunciado pedir.

Permissões e posse de arquivos

Cada arquivo tem um usuário dono, um grupo dono e permissões para três classes: dono, grupo e outros. Cada classe é um dígito octal que soma:

BitValorEm arquivoEm diretório
r4lerlistar
w2escrevercriar e apagar dentro
x1executarentrar (cd)
Modols -lSignificado
0700-rwx------só o dono lê, escreve e executa
0644-rw-r--r--dono lê e escreve; os demais só leem (padrão de arquivo)
0640-rw-r-----dono lê e escreve, o grupo lê, os outros nada. Bom para compartilhar só com quem você confia.
0755-rwxr-xr-xsó o dono modifica; todos executam (padrão de executável)
0600-rw-------privado (chaves, senhas)
  • No ls -l, a 1ª coluna traz o tipo + rwx do dono, do grupo e dos outros; depois vêm o usuário dono e o grupo dono.
  • O 0 na frente indica octal em C: 0644 ≠ 644!
  • O mode final é mode & ~umask (o umask, tipicamente 022, retira permissões).
  • Rodando com sudo, o arquivo criado pertence ao root. Ajuste com sudo chown usuario:grupo arq e chmod 644 arq.
  • Abrir sem permissão faz open retornar -1 com errno == EACCES ("Permission denied"). Sempre cheque o retorno.
  • Metadados (tamanho, dono, permissões, datas) ficam em struct stat, obtida com stat()/fstat() (man 7 inode).

errno: diferenciando erros

#include <errno.h>
int fd = open(dest, O_WRONLY | O_CREAT | O_EXCL, 0644);
if (fd == -1) {
    if (errno == EEXIST) {           // já existe: pergunte antes de sobrescrever
        printf("Sobrescrever %s? (s/n) ", dest);
        // ... se sim: fd = open(dest, O_WRONLY | O_TRUNC);
    } else if (errno == EACCES) {
        printf("Sem permissão!\n");
    } else {
        perror("open");
    }
}

Resumo relâmpago

  • Use open(nome, O_RDONLY) para ler e open(nome, O_WRONLY|O_CREAT|O_TRUNC, 0644) para gravar. Sempre teste == -1.
  • read retorna o número de bytes lidos (0 = EOF, -1 = erro). Nunca põe o '\0'.
  • write(fd, buf, n): use o n que você leu ou gerou com snprintf.
  • Os fds 0, 1 e 2 são stdin, stdout e stderr. Feche o que você abrir.
  • Permissões em octal: r=4, w=2, x=1, na ordem dono/grupo/outros.
  • Includes: <fcntl.h>, <unistd.h>, <sys/stat.h>, <errno.h>. Manuais: man 2 open, man 2 read, man 2 write, man chmod.
